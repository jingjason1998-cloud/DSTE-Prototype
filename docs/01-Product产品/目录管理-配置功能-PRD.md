## 一、文档说明

### 1.1 编写目的

本文档是 DSTE 平台「目录管理配置功能」的独立产品需求文档，用于：
- 统一各业务模块（知识中心、报表平台、规则引擎、战略专题等）对目录/分类树的管理方式
- 明确目录树形结构的增、删、改、重命名、拖拽排序及权限控制规则
- 为开发、测试、设计提供单一事实源
- 作为后续各模块接入目录配置能力的对接标准

### 1.2 变更历史

| 版本 | 日期 | 变更人 | 变更内容 |
|------|------|--------|----------|
| v1.0 | 2026-07-27 | 产品/技术 | 初稿：通用目录管理配置功能（树形目录 + 增删改重命名 + 拖拽排序） |

### 1.3 术语表

| 术语 | 说明 |
|------|------|
| 目录（Catalog/Directory） | 一种树形结构的数据组织单元，用于对业务实体进行分类、分组、导航 |
| 目录树（Catalog Tree） | 由目录节点按父子关系组成的层级结构 |
| 目录节点（Node） | 目录树中的单个目录项，包含 id、name、parentId、sortOrder 等元数据 |
| 业务域（Scope） | 目录的归属范围，用于隔离不同模块的目录数据，如 `knowledge`、`report`、`rule`、`strategy-topic` |
| 引用计数（RefCount） | 该目录下已挂载业务实体的数量，删除或合并时用于提示风险 |
| 路径快照（Path Snapshot） | 目录在某个时刻的完整路径文本，用于历史记录展示 |
| 拖拽排序（Drag & Drop Sorting） | 通过拖拽调整目录节点在同一父级下的顺序或变更父子关系 |

## 二、产品定位与边界

### 2.1 模块定位

「目录管理配置功能」是 DSTE 的**通用基础配置能力**，为各业务模块提供统一的树形目录维护入口：

- **统一维护**：各模块不再各自实现目录管理，统一调用目录管理能力
- **树形组织**：支持多级目录，满足知识中心、报表平台、规则分类等场景
- **灵活配置**：支持增删改、重命名、拖拽排序，适应业务结构调整
- **安全可控**：删除/移动目录时校验引用计数，避免误删导致业务数据失焦

### 2.2 核心价值

1. **降低重复建设**：知识中心、报表平台、规则引擎等场景共用一套目录管理能力
2. **提升配置效率**：树形拖拽维护，比表单级操作更直观
3. **保障数据安全**：引用校验、软删除、操作留痕，降低误操作风险
4. **支持多端复用**：目录数据可被 PC 端、移动端、AI 助手统一消费

### 2.3 功能边界

| 范围 | 说明 |
|------|------|
| **做** | 目录的创建、编辑、删除、重命名、启用/禁用；树形目录的展开/收起；同父级/跨父级拖拽排序；引用计数校验；目录与业务实体的关联配置 |
| **不做** | 文件上传与存储（仅管理目录元数据）；目录级权限隔离到具体业务数据；版本diff对比；目录的跨业务域迁移 |
| **限制** | 目录层级建议不超过 5 层；同一父节点下目录名称唯一；删除含引用的目录需先解绑或强制迁移 |

## 三、用户角色与场景

### 3.1 角色定义

| 角色 | 职责 | 核心场景 |
|------|------|----------|
| **系统管理员** | 维护平台级目录结构 | 初始化业务域目录、调整一级目录、恢复误删目录 |
| **业务配置员** | 维护本业务域的目录结构 | 在知识中心/报表平台下新增、重命名、排序目录 |
| **普通用户** | 消费目录结构 | 按目录浏览、筛选、定位业务实体 |
| **AI 助手** | 读取目录结构 | 基于目录理解业务分类，辅助检索与推荐 |

### 3.2 用户故事

| 编号 | 角色 | 故事 | 验收点 |
|------|------|------|--------|
| US-01 | 业务配置员 | 我希望新增一个目录，用于归类新类型的知识资产 | 可输入目录名称、选择父目录、保存后实时出现在目录树中 |
| US-02 | 业务配置员 | 我希望重命名已有目录，以匹配业务变化 | 编辑名称后，引用该目录的业务实体展示名称同步更新 |
| US-03 | 业务配置员 | 我希望删除不再使用的目录 | 空目录可直接删除；非空目录提示引用数量并要求迁移或解绑 |
| US-04 | 业务配置员 | 我希望通过拖拽调整目录顺序和层级 | 拖拽后目录树即时重排，持久化到服务端，刷新不丢失 |
| US-05 | 系统管理员 | 我希望区分不同业务域的目录，避免互相影响 | 不同 scope 的目录数据隔离，配置入口可按 scope 过滤 |
| US-06 | 普通用户 | 我希望按目录快速定位内容 | 目录树支持展开/收起、搜索高亮、点击筛选 |

## 五、数据模型

### 5.1 目录节点（CatalogNode）

```typescript
interface CatalogNode {
  id: string;                    // 目录唯一标识，UUID
  scope: string;                 // 业务域，如 knowledge / report / rule
  parentId: string | null;       // 父目录 ID，根目录为 null
  name: string;                  // 目录名称
  fullPath: string;              // 路径快照，如 "战略专题/战区专题/华东战区"
  sortOrder: number;             // 同父级排序序号
  icon?: string;                 // 图标标识（可选）
  status: 'active' | 'disabled'; // 启用/禁用
  refCount: number;              // 引用计数
  level: number;                 // 层级深度，根目录为 1
  isDeleted: boolean;            // 软删除标记
  createdAt: string;             // ISO 8601
  updatedAt: string;             // ISO 8601
  createdBy: string;             // 创建人 ID
  updatedBy: string;             // 最后更新人 ID
}
```

### 5.2 目录关系

```typescript
interface CatalogRelation {
  ancestorId: string;   // 祖先节点 ID
  descendantId: string; // 后代节点 ID
  depth: number;        // 层级差，直接父子为 1
}
```

> 说明：采用 closure table（闭包表）或 materialized path 方案存储层级关系，便于快速查询某节点的所有子树。具体实现由技术方案决定。

### 5.3 业务实体关联（CatalogBinding）

```typescript
interface CatalogBinding {
  id: string;
  scope: string;        // 业务域
  catalogId: string;    // 目录 ID
  entityType: string;   // 业务实体类型，如 knowledge / report / rule
  entityId: string;     // 业务实体 ID
  createdAt: string;
}
```

## 六、接口设计（REST）

### 6.1 目录接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/catalogs?scope={scope}` | 获取某业务域的完整目录树 |
| POST | `/api/catalogs` | 创建目录 |
| PATCH | `/api/catalogs/{id}` | 更新目录（名称、图标、状态等） |
| DELETE | `/api/catalogs/{id}` | 删除目录 |
| POST | `/api/catalogs/{id}/move` | 移动目录（含拖拽排序） |
| GET | `/api/catalogs/{id}/refs` | 获取目录引用列表 |

#### 创建目录请求示例

```json
POST /api/catalogs
{
  "scope": "knowledge",
  "parentId": "cat-001",
  "name": "最佳实践",
  "icon": "book"
}
```

#### 移动目录请求示例

```json
POST /api/catalogs/cat-006/move
{
  "parentId": "cat-002",    // null 表示提升为根目录
  "sortOrder": 2
}
```

### 6.2 状态码

| 状态码 | 场景 |
|--------|------|
| 200 | 查询/更新成功 |
| 201 | 创建成功 |
| 204 | 删除成功 |
| 400 | 参数非法（如名称重复、层级超限、循环依赖） |
| 409 | 目录存在引用，无法删除 |
| 404 | 目录不存在 |
| 403 | 无权限 |

## 十、边界与异常

| 场景 | 处理规则 |
|------|----------|
| 删除含引用的目录 | 提示引用数量，禁止删除；提供「查看引用」入口 |
| 删除含子目录的目录 | 提示需先删除子目录，或提供级联删除（管理员） |
| 重命名为已存在名称 | 提示「该目录下已存在同名目录」 |
| 拖拽导致循环依赖 | 禁止放置，光标变为禁止样式 |
| 拖拽后层级超过 5 层 | 禁止放置，提示「目录层级不能超过 5 级」 |
| 网络异常保存失败 | 保留本地变更状态，提示重试；撤销本次拖拽展示 |
| 多人同时修改同名 | 后保存者收到冲突提示，需刷新后重试 |

| CONF-03 | 是否需要目录模板/初始化数据 | 每个接入业务域须提供默认目录模板；默认模板与现有系统保持一致，首期沿用战略执行板块既有目录结构 | 已确认 |
| CONF-04 | 拖拽排序的具体交互细节 | 采用 Ant Design Tree 的 drag-and-drop 方案：放置线表示同层级排序，放置框表示成为子节点；悬停 800ms 自动展开目标节点 | 已确认 |
| CONF-05 | 是否支持目录图标自定义 | 支持从设计系统图标库选择图标，首期提供 20 个常用图标 | 已确认 |
